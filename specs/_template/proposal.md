## Goal

**例**：

## Non-Goals

至少列 **2 条**"本次明确不做"。这是控制 scope 最有效的字段。

- 不做：批量重评所有学员（本次只重评单份）
- 不做：重评成功后发邮件通知（暂无邮件系统）
- 不做：重评历史的审计日志（未来需求）

## 用户价值

谁用 / 用来干什么 / 解决什么痛点？

- 谁：管理员
- 用途：发现某次评分出现"评分失败"时手动触发重跑
- 痛点：现在没有 UI 入口，只能 SSH 上服务器手动调函数

## 范围

涉及哪些模块 / 文件？粗粒度即可，详细在 design.md。

- 后端：新增 `POST /api/admin/regrade` route
- 前端：dashboard 添加按钮 + 点击行为 + 反馈 toast
- 不涉及：评分逻辑本身（`lib/grading.ts` 中 `regradeFailedQuestions` 已实现）

## 风险

风险 = 可能让任务失败 / 出错 / 需要返工 的因素。

- 真实 LLM 模式下重评会调外部 API，可能超时
- 同一份 exam 被并发重评 N 次会浪费配额
- 学员可能误以为按钮能重评客观题
